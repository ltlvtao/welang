# ADR-0001：docs/ 下英文权威的双语文档

- 状态：已接受
- 日期：2026-09-03
- 决策出处：openspec 变更 `dual-language-docs`

## 背景

项目交互语言是中文，而 `docs/` 原本只有英文。单一语言无法同时服务中文阅读的主要受众与英文的生态/工具价值（规范增量是英文的字面片段、提交信息为英文、标识符与诊断术语为英文）。

## 决策

`docs/` 下的文档提供双语同步支持：

1. **英文为权威文本。** 规范增量以英文书写并逐字合并进英文正典；中文渲染是同步翻译。任何不一致以英文为准，翻译在引入分歧的同一变更内修正。
2. **兄弟文件布局。** 每个 `*.md` 在同目录有配对的 `<basename>.zh.md`，继承全部命名元素（数字前缀、ADR 编号）。
3. **只做结构检查。** `openspec/tools/docs_sync.py` 检查配对、标题层级计数、围栏代码块计数。翻译的语义等价由变更评审承担，不由脚本承担。
4. **独立于 `validate.py`。** 两个校验器职责、触发条件、失败语义不同；在验证阶梯中各占一行。

## 后果

- 文档写作与评审工作量约翻倍；已接受。
- 触及 `docs/` 的变更在翻译更新且 `docs_sync.py` 通过之前不得进入 `complete`。
- `docs/` 之外的文件按设计保持单语（`AGENTS.md`、`openspec/`、`.agents/` 中文；代码注释与提交信息英文）。

## 被拒替代方案

- **中文权威文档：** 会推翻"规范增量是英文的字面片段"规则，并使正典与英文标识符、诊断术语脱节。被拒（用户裁决，2026-09-03）。
- **平行树（`docs/` + `docs-zh/`）：** 路径维护翻倍、需要跨树改写链接、更易产生孤儿。被拒。
- **单文件双语（语言交替）：** 无法按单语言渲染；diff 噪声大；锚点歧义。被拒。
- **将 `docs_sync.py` 并入 `validate.py`：** 把文档配对与变更工件结构耦合，触发条件不同。被拒。
