# ADR-0003：shadow-stack 根登记 + stop-the-world 精确标记清除

- 状态：Accepted（以英文版为准）
- 日期：2026-09-07
- 决策于：openspec 变更 `stdlib-and-gc`

## 背景

ADR-0002 将自建运行时划入产品范围，精确回收包含在内。M8 落地第一个真实收集器，诚实的起步形态至关重要：M8 程序是单线程直线 main 体；编译器掌握每个 gc 引用的生存期（构造协议在分配处根化对象）；并发、分代、移动式都还没有可实证的表面。本决策需要一个从第一天起就精确、尽可能少冻结进 ABI、并为每项被推迟技术命名再入场门的设计。

## 决策

1. **根协议是 shadow stack。** 编译器在 gc 引用的生存期边界生成 `__we_root_push(ptr)` / `__we_root_pop()`；运行时维护根栈（线程局部——M8 单线程期间即全局）。精确性由构造保证：每个根都是编译器插入的 GC 对象指针，整个设计里不存在保守栈扫描。
2. **收集是 stop-the-world 精确标记清除。** 对象携带冻结头 `{ map@0, size@8 }`，载荷自偏移 16 起。`map` 指向该类型的布局描述符——编译器生成的 IR 常量，承载引用位图：每 64 个载荷槽一字，bit *i* 置位当 `16 + 8*i` 处的字是 gc 引用；String 双字不是引用。标记位骑在所存 map 字的 bit 0（描述符 ≥8 对齐），自由块标记骑在 size 的 bit 0（size 8 对齐）——无额外头字、无陈旧状态位：清扫从 chunk 前缀重建 free-list，块的自由性只活在重建后的表里。
3. **分配在 1 MiB chunk 内 bump，free-list 上 first-fit**（余量容得下块头时分裂）。刻出字节超阈值时在 `__we_alloc` 入口触发收集——构造协议使入口即安全点：活集全在根栈上，在飞块尚未刻出。
4. **冻结 ABI 是 `__we_alloc(i64) ptr` / `__we_free(ptr)`**——与 M4 承诺一致，不变。运行时写头的 size 位并返回零化块；编译器的构造代码存 map 指针。本 ADR 记录的新运行时符号：根对、`__we_gc_collect()`（测试与探针面，非 We 语言面）、以及第 2 条的描述符约定。
5. **构造协议是 alloc → map store → 立即 root push → 按源序字段 store。** 外层对象在任何字段值求值前根化，嵌套分配绝不会在父对象未根化时与收集竞态。
6. **演进路由**（记录于此，刻意不在 M8 落地）：M9 的并发工作开启「分代 + 写屏障 vs 并发标记」决策门；LLVM stack map（`gc "..."` 属性）是消除 shadow-stack push/pop 开销的路由；移动式（压缩式）收集经读屏障代价评估入场。描述符与精确根集已存在，每条路由都继承精确堆遍历。

## 后果

- stop-the-world 对 M8 的单线程程序是诚实选择；暂停预算保持为实现质量目标（ADR-0002 机制中立纪律），仅经规范层变更成为规范承诺。
- stack map 落地前每次构造都付出 root push/pop 调用——有界、可测的成本，为 M8 集接受。
- 描述符约定与精确根集是后续一切收集器继承的资产；演进路由上冻结 ABI 与头布局都无需破坏。
- 清扫返回新死块数（已在 free-list 上的块不计入再入表）——存活探针钉住的探针可观测语义。

## 被拒替代方案

- **保守栈扫描：** 读取不精确、钉住假阳性、提前封死移动式路由——与 ADR-0002 精确回收承诺不兼容。
- **引用计数：** 循环仍需 tracing 兜底，原子计数给单线程场景徒增负担。
- **立即上 LLVM stack map：** 正确的长期根承载，但要花掉 M8 接受集之外的 codegen 投入；记为演进路由。
- **立即上移动/压缩式收集：** M8 规模无碎片压力，读屏障代价未测；只经其评估门入场。
