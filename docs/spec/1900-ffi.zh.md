# We 语言规范 —— 第 19 章：FFI

### Requirement: foreign 块

foreign 块是 `foreign "c" { items }` 形的顶层项（第 6 章修订后的枚举）：`foreign` 关键字——自初始清单起由第 1 章预留、其语法由本章批准——该位置上恰为字符串字面量 `"c"` 而非他物、以及一个第 2 章块，块内按本章持 foreign 函数声明与不透明类型声明，别无他物。该字符串命名本规范定义的互操作边界——C ABI，第 0 章的宿主策略钦定 `foreign "c"` 为唯一载体（v0.8 的 Go 后端字符串不继承；Go 生态互操作经 C 桥另作决策）。该位置任何其他字符串字面量以 `E1701:` foreign block's ABI string is not "c" 拒绝。出现在顶层之下任何位置的 foreign 块——函数体内、任何嵌套块内——以 `E1702:` foreign block outside the top level 拒绝。foreign 块声明的名字恰如普通声明一样加入模块单一名字空间（重复 `E0404`，第 6 章），每个被声明条目 MAY 携 `pub`，其自导入模块的到达依第 15 章与任何 pub 声明同治。一个模块 MAY 持数个 foreign 块；它们的全部条目共享同一名字空间。

#### Scenario: foreign 块解析为顶层项

- **WHEN** 模块持有 `foreign "c" { record Socket { }  fn connect(addr: String) -> Socket effect io }`
- **THEN** 该块解析为一个顶层项；`Socket` 与 `connect` 加入模块名字空间，二者上的 `pub` 依任何 pub 声明之法治其到达

#### Scenario: ABI 字符串恰为 "c"

- **WHEN** `foreign "c" { }` 出现在模块顶层
- **THEN** 该块即本章定义的互操作边界——空条目列表合法、什么都不声明

#### Scenario: 其他字符串被拒绝

- **WHEN** `foreign "go" { }` 或 `foreign "llvm" { }` 出现
- **THEN** 编译器以 `E1701:` foreign block's ABI string is not "c" 拒绝；载体由第 0 章宿主策略钦定，扩展它是本章的 spec 层修订

#### Scenario: 顶层之下的 foreign 块被拒绝

- **WHEN** `foreign "c" { ... }` 块出现在函数体内
- **THEN** 编译器以 `E1702:` foreign block outside the top level 拒绝；边界按模块声明、不按表达式

#### Scenario: 跨块重名被拒绝

- **WHEN** 一个模块持两个 foreign 块、各自声明 `fn open`，或一个 foreign 块声明 `record Socket` 而顶层另有 `record Socket { ... }`
- **THEN** 编译器以 `E0404:` duplicate name in one module 拒绝第二个声明；foreign 块的名字入同一名字空间

#### Scenario: foreign 块只持声明

- **WHEN** `foreign "c" { let x = 1 }` 或 `foreign "c" { effect gpio }` 出现
- **THEN** 编译器依第 2 章 `E0105` 拒绝该条目——块内持 foreign 函数声明与不透明类型声明，别无他物；绑定与效果声明各守自己的顶层形式

### Requirement: foreign 函数声明

foreign 块内的函数声明是无体的第 6 章签名形：`fn name(params) effect tag1 tag2 ...` 或 `fn name(params) -> type effect tag1 tag2 ...`——名字依第 1 章约定、完全标注的参数依第 6 章、`->` 后可选的声明返回、以及第 16 章拼写的效果段居参数表与箭头或声明末尾之间。段是 REQUIRED 的，这是边界自身的要求：普通声明省略的段是其体可查的纯声明（第 16 章），而 foreign 声明无体——声明是被调用者效果仅有的证据——故省略以 `E1703:` foreign function declaration without an effect segment 拒绝，纯 foreign 函数写零标签的裸段 `effect`——仅此处合法的拼写，声明在此没有体可查它。声明 MUST NOT 携泛型参数子句：foreign 块内 `fn name<T>(params) ...` 以 `E1704:` foreign function declaration with a generic clause 拒绝——原生侧只认识一个签名，按应用实例化是本规范不批准的生成故事；边界是单态的。foreign 函数不声明体，体在此不拟合任何产生式（`E0105`，第 2 章）。被声明的名字对其调用而言是普通函数名：调用它是普通调用（第 16 章 `E1401` 在调用位裁决、第 15 章 `E1304` 于未解析时），声明本身是工具链章解析到原生符号的那个绑定——如何解析，是那一章的事、非本章的。调用形是 foreign 名唯一已批的用法：第 12 章的值域是第 6 章的顶层 fn，foreign 名在值位不拟合任何产生式——依第 2 章 `E0105` 拒绝，方法值先例——因为值为码指针的名字是回调问题的 We 侧同面，随之一并延后（不检查之余）；届时包装闭包 `|x| abs(x)` 是路线，其推断是第 12 章与第 16 章的普通事务。

#### Scenario: 带标签的声明解析

- **WHEN** `foreign "c" { }` 内出现 `fn write(fd: Int64, buf: Bytes) -> Int64 effect io`
- **THEN** 声明带居参数表与箭头类型之间的段解析；函数入名字空间、其调用对照声明集合检查

#### Scenario: 纯声明写裸段

- **WHEN** `foreign "c" { }` 内出现 `fn abs(x: Int64) -> Int64 effect`
- **THEN** 裸段——仅 foreign 块内合法——显式陈述纯声明；`abs` 的调用方不为调用欠任何效果

#### Scenario: 无段的声明被拒绝

- **WHEN** `foreign "c" { }` 内出现 `fn dial(addr: String) -> Socket` 而无段
- **THEN** 编译器以 `E1703:` foreign function declaration without an effect segment 拒绝；没有体可对照查证纯声明，故声明必须写出来

#### Scenario: 泛型声明被拒绝

- **WHEN** `foreign "c" { }` 内出现 `fn id<T>(x: T) -> T effect`
- **THEN** 编译器以 `E1704:` foreign function declaration with a generic clause 拒绝；逐实例化声明，或把多态包进调用单态声明的 We 侧泛型函数

#### Scenario: 函数体不拟合产生式

- **WHEN** foreign 声明后随一个块
- **THEN** 编译器依第 2 章 `E0105` 拒绝——foreign 声明是签名；原生侧持有体

#### Scenario: foreign 名不是值

- **WHEN** `let f: fn(Int64) -> Int64 = abs` 出现而 `abs` 是 foreign 声明，纯与否皆然
- **THEN** 编译器依第 2 章 `E0105` 拒绝——调用形是该名字的唯一用法；`|x| abs(x)` 是旅行的包装

### Requirement: 不透明 foreign 类型

foreign 块内的不透明类型声明是第 8 章类别拼写的零字段 record：`record Socket { }`、`byval record Socket { }`、`byres record File { }`——类别前缀原样携带第 8 章语义，空字段列表携带不透明性：这样声明的类型定义在原生侧，We 代码持其值为句柄、别无他物。零字段正是第 8 章已容许 record 之事，该声明恰复用那个产生式——此处不存在新 record 形式，只有给予所声明 record 不透明纪律的位置。不透明类型的值仅经跨界进入 We 代码——foreign 函数的声明返回——且仅经跨界或 gc 值的普通遗忘离开；该类型 MUST NOT 在 We 侧被构造或更新：`Socket { }` 作为构造表达式会空真满足第 8 章的全字段恰一次、凭空造出句柄，以 `E1707:` construction or update of a foreign opaque type 拒绝，更新表达式 `{ ... with &old }` 以同码落于同因。不透明类型不存在可访问的字段，对其字段访问依第 8 章 `E0604` 解析。`byres` 不透明类型与任何资源 record 同治：其声明模块 MUST 为其持有 `impl Releasable`（第 13 章 `E1101`，声明完备性义务原样继承），该 impl 的体是普通受检代码——调用 foreign `close` 函数就是释放的实现方式。普通接口在不透明类型上的 impl 依第 10 章规则合法，如同模块自己声明的任何名义类型；不透明性不豁免也不延伸 impl 纪律。

#### Scenario: 各类别的不透明类型皆解析

- **WHEN** 出现 `foreign "c" { record Socket { }  byval record Errno { }  byres record File { } }`
- **THEN** 各声明其前缀类别的不透明类型——gc 句柄按引用共享、值按拷贝携带、资源在第 13 章完整纪律之下

#### Scenario: 句柄仅经跨界进入

- **WHEN** 声明 `fn accept(sock: Socket) -> Socket effect io` 且 We 函数绑定调用的返回
- **THEN** 被绑定的值是像任何该类型值一样的 `Socket`；它在原生侧被造出，没有 We 侧产生式造它

#### Scenario: 构造被拒绝

- **WHEN** `Socket { }` 作为表达式出现
- **THEN** 编译器以 `E1707:` construction or update of a foreign opaque type 拒绝；第 8 章规则的零字段空真满足正是该码关死的洞

#### Scenario: 更新同样被拒绝

- **WHEN** `Socket { ... with &sock }` 作为表达式出现
- **THEN** 编译器以 `E1707:` construction or update of a foreign opaque type 拒绝；拷贝句柄的不存在字段是变装的凭空造值

#### Scenario: byres 不透明类型配其 impl

- **WHEN** foreign 块内声明 `byres record File { }` 且模块按第 13 章持有 `impl Releasable for File { fn release(mut self) { close(self as ...) } }`
- **THEN** 义务是第 13 章自己的 `E1101` 检查——impl 缺失在那里被拒，而在场时 impl 的体是调用 foreign `close` 的普通代码

### Requirement: 跨界类型集

foreign 函数的每个参数类型与每个声明返回类型 MUST 恰持跨界集：第 7 章八个整数类型、`Float32`、`Float64`、`Bool`、`Rune`、`String` 与 `Bytes`——仅参数位——不透明 foreign 类型——本模块自己的或经第 15 章 pub 规则到达的另一模块的——以及 `Never`——仅声明返回位。集合之外的任何类型——参数位的 `Never` 在内——以 `E1705:` foreign function signature holds a type outside the crossing set 拒绝：带字段 record、sum、元组、`List`、`Map`、`Set`、`Option`、`Result`、闭包与函数类型、`Dyn`、泛型参数——一概不跨界。值一次一个、按基类型的 C ABI 布局跨界，否则根本不跨界；组合值的编组是 We 侧代码——显式的逐字段调用、经 foreign 函数填充的缓冲——绝不是编译器执行的隐藏转换（第 7 章 `E0501` 在此如处处成立：这个边界也不存在隐式转换）。`String` 与 `Bytes` 仅作参数跨界——没有返回约定说谁拥有原生分配、它多长、谁释放它，把答案留给逐声明文档的边界不可检查——故声明的 `String` 或 `Bytes` 返回以 `E1706:` String or Bytes is not a foreign return type 拒绝。`Never` 返回是不返回之声明，合法且披露：这是该边界上类型系统唯一信以为真的声明——普通 `Never`（panic 族）由运行时保证，foreign 的只由原生侧保证，声明 `Never` 却照样返回的 foreign 函数是本规范保证之外的原生侧未定义行为——在此陈述而非隐藏。

#### Scenario: 标量跨界

- **WHEN** 声明 `fn mix(a: Int64, b: UInt8, c: Float64, d: Bool, e: Rune) -> Int32 effect io`
- **THEN** 签名解析；每个类型都在跨界集内、值按其 C ABI 布局旅行

#### Scenario: 不透明类型两向跨界

- **WHEN** `byres record File { }` 在作用域内，声明 `fn open(path: String) -> File effect io`
- **THEN** 参数与返回都在集内——句柄出去、资源回来

#### Scenario: 导入的不透明类型跨界

- **WHEN** 模块 `net` 持 `foreign "c" { pub record Socket { }  pub fn socket() -> Socket effect io }` 而模块 `app` 在自己的 foreign 块内声明 `fn probe(s: net.Socket) -> Bool effect`
- **THEN** `net.Socket` 在跨界集内——该类型是名义的、经 pub 到达——声明解析；foreign 条目上的 `pub` 正是使类型可自他处跨界者

#### Scenario: 组合类型被拒绝

- **WHEN** 声明 `fn sum(xs: List<Int64>) -> Int64 effect io` 或 `fn now() -> (Int64, Int64) effect io`
- **THEN** 编译器以 `E1705:` foreign function signature holds a type outside the crossing set 拒绝；在 We 侧编组，一次调用一个值

#### Scenario: 函数类型被拒绝

- **WHEN** 声明 `fn registerCallback(cb: fn(Int64) -> Int64) effect io`
- **THEN** 编译器以 `E1705:` foreign function signature holds a type outside the crossing set 拒绝——连同回调问题本身，由本变更延后（不检查之余）

#### Scenario: String 返回被拒绝

- **WHEN** 声明 `fn errmsg() -> String effect io`
- **THEN** 编译器以 `E1706:` String or Bytes is not a foreign return type 拒绝；惯用法是不透明句柄加长度查询加拷入调用方缓冲

#### Scenario: Never 声明不返回

- **WHEN** 声明 `fn exit(code: Int64) -> Never effect io` 且 We 函数调用它
- **THEN** 声明解析且调用依第 9 章规则按发散处理——信任已披露：该声明的担保人是原生侧、不是运行时

### Requirement: 边界处的 String 与 Bytes

`String` 实参以对其字节的只读借用跨界：调用期间被调用方按 C ABI 指针形收到字节；被调用方 MUST NOT 写它们、MUST NOT 在返回后持有该指针。`Bytes` 实参以其字节与其长度跨界——调用期间的一对 (pointer, length)；缓冲惯用法——被调用方在调用期间写入调用方提供的缓冲——正是该形式为之存在的模式，这样写成的写在返回后经 We 侧别名可见，该可见性是此惯用法言明的代价：gc 值依第 8 章按引用共享，经借出对写过的缓冲是就地写的。这些是原生侧的契约，在此陈述、无处检查：跨界入 C 即离开本规范的受检世界——We 侧的检查（类型、效果、所有权）完整，原生侧的内存行为是它自己的契约，边界的诚实在于它如实说出自己不能检查什么（第 0 章，原则 8）。没有 `String` 或 `Bytes` 值经任何其他路线跨界：二者都不是 foreign 返回类型（`E1706`），也不存在把借出指针转回 We 值的转换——出自原生代码的字符串经不透明句柄与显式拷贝而来。

#### Scenario: String 以只读借用跨界

- **WHEN** 声明 `fn puts(s: String) effect io` 并以 We `String` 调用
- **THEN** 被调用方在调用期间收到字节；写它们或在返回后持有指针是原生侧对已言明契约的违反——在编译器检查之外、在本规范所固定内容的记录之内

#### Scenario: Bytes 实参即缓冲惯用法

- **WHEN** 声明 `fn read(fd: Int64, buf: Bytes, cap: Int64) -> Int64 effect io` 并以 We 侧缓冲调用
- **THEN** 被调用方可于调用期间向借出缓冲写 `cap` 字节；返回后这些写经缓冲的每个别名可见，如第 8 章的引用共享所言

#### Scenario: 借出的指针不成为 We 值

- **WHEN** We 函数想要不透明 `CString` 句柄的文本
- **THEN** 路线是 foreign 调用——长度查询、We 侧 `Bytes`、拷贝调用——没有任何产生式把借出指针变成 `String` 或 `Bytes`；回来的只有跨界集所容的

### Requirement: 边界处的效果

foreign 函数声明的段是其调用的全部效果真相：调用它是普通调用、效果集即声明集，第 16 章 `E1401` 裁决原样适用——声明集不含被调用者标签的语境发出的调用在那里被拒，foreign 与否无别。foreign 声明可携的标签是第 16 章下其位置合法的标签：内建标签（`io`、`net`、`time`）、本模块自己的标签、经第 16 章到达规则合格的导入标签。裸 `effect` 段——仅在此拼出的纯声明——声明调用不执行任何效果，调用方不为调用欠任何东西，该声明如这里每个声明一样落在原生侧身上。foreign 声明中没有任何东西改变效果归属：段随声明行进、进入调用方语境执行的每一项检查。

#### Scenario: 调用对照调用方集合检查

- **WHEN** 纯 We 函数调用声明 `effect io` 的 foreign 函数
- **THEN** 编译器以 `E1401:` undeclared effect at a call 拒绝——边界不添加豁免；调用就是调用

#### Scenario: 自定义标签随声明跨界

- **WHEN** 模块声明 `effect gpio` 且其中 foreign 声明携带 `effect gpio`
- **THEN** 声明 `gpio` 的调用方可调用它、别无他人；模块标签对 foreign 声明的统辖恰如对 We 声明

#### Scenario: 纯声明调用方零欠

- **WHEN** 无段的 We 函数调用以裸 `effect` 声明的 foreign 函数
- **THEN** 不触发任何效果诊断；纯声明是声明侧的，调用方语境看见一个纯调用

### Requirement: 边界处的资源

所有权以类型跨界，携带它的是零新规则：`byres` 不透明类型的参数是第 13 章的实参传递通道——调用方的释放义务随签名转移，被调用方的原生侧在调用后持有句柄即该章的单句柄纪律；`byres` 不透明类型的声明返回交付一个义务在绑定处附着的值——`scope resource` 绑定它、作用域出口机制恰一次释放它，配对的 `E1101` impl 即释放之体。`gc` 不透明句柄作为 gc 值跨界——按引用共享、可安全别名、遗忘是 gc 的事；`byval` 不透明值按拷贝跨界。第 13 章的三通道、单释放触发、组合位禁令在此边界原样成立：资源绝不进入它在纯 We 代码中进不了的 `List`、`Dyn` 箱或 task 捕获（处处 `E1106`），边界只加类型、不加规则。

#### Scenario: 资源经参数跨界

- **WHEN** 持有 `byres` 不透明类型 `scope resource` 绑定的 We 函数把它作为实参传给声明该参数的 foreign 函数
- **THEN** 义务经第 13 章实参通道转移；绑定的作用域不再释放它，签名说了它去了哪里

#### Scenario: 资源经返回跨界

- **WHEN** foreign 函数的声明返回是 `byres` 不透明类型且调用的值以 `scope resource` 绑定
- **THEN** 义务在绑定处附着、作用域出口机制一次释放它；句柄原生造出、释放而去，全部在第 13 章既有规则之下

#### Scenario: 组合位禁令原样成立

- **WHEN** `byres` 不透明值被放入 `List`、装进 `Dyn`、或被 task 块捕获
- **THEN** 编译器依第 13 章 `E1106` 恰如对 We 资源 record 那样拒绝；不透明性对该禁令不改变什么

### Requirement: 不检查之余

这个边界不固定的东西，它指名道姓。原生侧的内存行为——借用后持有、写入 `String` 的字节、声明 `Never` 却照样返回——在本规范的检查之外：设计把每个可检查事实留在 We 侧、其余如实陈述为原生侧契约。回调被延后，延后有两面：函数类型在跨界集之外（`E1705` 盖签名位——交给原生的 fn 值），foreign 名在值位不拟合任何已批产生式（`E0105`，foreign 函数声明——值为码指针的名字，边界哪一侧都一样）。fn 指针的故事——回调体的效果归属哪个声明、哪个运行时上下文运行它、哪个调用约定携带它——没有已批答案；缺口在此登记、留给未来变更整体设计，而不是留给一次修订开一道缝。链接——声明名如何绑定到原生符号、名修饰、库搜索、平台 C ABI 之外的调用约定变体——是工具链章的事务、非本章的（第 0 章机制中立纪律：spec 定义可观察语义与检查，工具链承载构建）；此处不固定任何工具链行为，而标准库自己的 foreign 声明恰如用户代码的一样遵循本章规则——不存在特权语法通道（第 0 章，原则 6）。

#### Scenario: 回调提案须回答已登记的问题

- **WHEN** 后续变更提议在此边界接纳函数指针
- **THEN** 它在任何签名持有函数类型之前回答三个已登记问题——回调体的效果归属、其执行的运行时上下文、调用约定——否则仅凭本要求即遭拒绝

#### Scenario: 标准库依同一规则跨界

- **WHEN** `std.io` 把它的文件函数声明为 foreign 声明
- **THEN** 它们依本章产生式解析、依本章规则检查，恰如用户模块的；库不持有第二语法

### Requirement: FFI 诊断段位

FFI 章拥有注册表段位 `E1700`–`E1799`，声明于 `docs/spec/diagnostics.toml` 的 `[segments]`。分配：`E1701` foreign block's ABI string is not "c"、`E1702` foreign block outside the top level、`E1703` foreign function declaration without an effect segment、`E1704` foreign function declaration with a generic clause、`E1705` foreign function signature holds a type outside the crossing set、`E1706` String or Bytes is not a foreign return type、`E1707` construction or update of a foreign opaque type。`E1700` 与 `E1708`–`E1799` 为本章修订保留——回调族在其中，待其问题被回答之时。触发语义在本章 Requirement 内；条目在注册表。

#### Scenario: 一个 FFI 码被发射

- **WHEN** 工具链发射任何 `E17xx` 诊断
- **THEN** 其完整条目可从 `docs/spec/diagnostics.toml` 以 owner `1900-ffi` 检索

#### Scenario: 后续变更需要本段位的码

- **WHEN** 回调变更或本章另一修订需要新诊断
- **THEN** 其变更在同一变更内于 `E1700`–`E1799` 内扩展注册表，或声明自己的段位

## 示例（非权威）

下列示例只用第 1–19 章已批准的表面形式。它们是说明性的、非权威的：任何冲突处以 Requirement 与 Scenario 为准。带诊断码注解的行是被拒绝的形式，展示编译器发射的码。

### 一个 foreign 模块

```we
foreign "c" {
    record Socket { }                         // gc handle, minted only by crossing
    byval record Errno { }                    // value carried by copy
    byres record File { }                     // resource — pairs impl Releasable below

    fn socket() -> Socket effect io
    fn connect(sock: Socket, addr: String) -> Int64 effect io
    fn errno() -> Errno effect                // bare segment: the pure claim
    fn abs(x: Int64) -> Int64 effect
}

// foreign "go" { }                           // E1701: foreign block's ABI string is not "c"
// fn nested() { foreign "c" { } }            // E1702: foreign block outside the top level
```

### 资源以类型跨界

```we
foreign "c" {
    byres record File { }

    fn open(path: String) -> File effect io
    fn read(fd: File, buf: Bytes, cap: Int64) -> Int64 effect io
    fn close(fd: File) effect io
}

impl Releasable for File {
    fn release(mut self) {                    // chapter 13's obligation, met by a call
        let _ = close(self)                   // the impl body is ordinary checked code
    }
}

fn load(path: String) -> Bytes effect io {
    scope resource f = open(path)             // obligation attaches at the binding
    let buf = Bytes(4096)
    let n = read(f, buf, 4096)
    buf
}                                             // scope exit releases f exactly once
```

### 调用即普通调用

```we
foreign "c" {
    fn abs(x: Int64) -> Int64 effect
    fn write(fd: Int64, buf: Bytes) -> Int64 effect io
    fn exit(code: Int64) -> Never effect io
}

fn pure(x: Int64) -> Int64 { abs(x) }         // bare segment: the caller owes nothing
// fn oops(x: Int64) -> Int64 { write(1, b) } // E1401: undeclared effect at a call
fn quit(code: Int64) effect io { exit(code) } // Never declared: the call diverges
```

### 编组是 We 侧代码

```we
foreign "c" {
    record CString { }                        // opaque handle — no String returns exist

    fn strlen(s: CString) -> Int64 effect
    fn memcpy(dst: Bytes, src: CString, n: Int64) effect io
}

fn textOf(s: CString) -> String {             // explicit copy, every step checked
    let n = strlen(s)
    let buf = Bytes(n)
    let _ = memcpy(buf, s, n)
    String.fromBytes(buf)                     // stdlib surface, not a crossing
}
```
