# Design: diagnostics-registry

## 决策 1：注册表形态——TOML 单文件、仅英文（用户裁决 2026-09-03）

`docs/spec/diagnostics.toml` 作为唯一注册表：`[segments]` 段位表 + `[diagnostic.EXXXX]` 逐码条目。仅英文。理由：可解析、可 diff、LLM 与未来编译器直接消费；单文件自包含，无派生漂移。被拒替代：**Markdown 章节列表**（机器可操作性弱，编译器需另维护映射）；**TOML 权威 + 派生双语列表**（派生文件漂移风险，当前无构建管线）。机器工件类（同类先例：change.yaml、validate.py、git hooks）无中文配对义务——docs_sync 仅扫 `*.md`（已核实 `rglob("*.md")`），TOML 天然豁免。编译器输出语言与本地化是工具链议题，留给诊断协议章节裁决，英文条目不是对它的预设。

## 决策 2：权威分工——章节=触发，注册表=条目，段位表也在注册表

章节的 Requirements/Scenarios 规定码**何时发出**（触发权威）；注册表持有每码**完整条目**与 `[segments]` 段位分配（条目权威 + 段位权威）。章节散文可引用码与段位区间（可读性），但不得重定义条目。依据：P2（单一书写路径）、P7（机器可操作修复）、"一类事实只有一个权威位置"。段内块结构（token 级/命名块/预留位）是第 1 章对自有段位内部的组织方式，留在章节文本；注册表不复制。validate.py 机械执法（决策 4）。

## 决策 3：注册表随提升更新（归档任务），不在 active 期间改

与章节提升同时机：active 窗口内增量承诺码位，注册表条目在归档任务中落盘。维持不变式"已提升表面互相一致"——任何时刻 docs/spec/*.md 中出现的 `EXXXX:` 用法都 ⊆ 注册表条目。变更内的一致性由关卡负责：审计点 3 对照注册表与 active 增量，code-review 点 4 措辞由"已在 spec 增量中登记"更新为"已在注册表中登记"。

## 决策 4：validate.py 五项检查（常开）

(a) TOML 解析 + 模式：必填七字段、severity ∈ {error, warning}、键名与 severity+号码一致；(b) **冒号模式用法 ⊆ 条目**：`docs/spec/**/*.md` 中 `[EW]\d{4}:` 形态（诊断调用形，恰为场景文本的 `` `E0001: invalid character` ``）必须对应注册表条目——区间端点（如 E0001–E0099）不带冒号，不触发；(c) 每条目 owner 文件存在且 requirement 标题在该文件中存在；(d) 条目号码落在 owner 章节拥有的已声明段位内；(e) E/W 同号冲突（E0500 与 W0500 不得并存）。仓库 Python 3.14.4，tomllib 标准库可用。docs/ 不存在时跳过注册表检查（保持工具可移植）。

## 决策 5：E/W 共享号码空间

同一四位数同一时刻至多一个严重级。理由：同号异义（E0500 错误 / W0500 警告并存）会让"按码取条目"退化为"按码+严重级取条目"，徒增 LLM 与工具的查找分支；警告复用已有号码空间也不产生额外收益。

## 决策 6：命名与放置——9900 章位 + 结构文件豁免

- 第 99 章 `docs/spec/9900-diagnostics-registry.md`：99×100，符合步长 100 约定；保留号段尾部给横切注册表类章节（正文内容章节从 0000 向后排，注册表类从尾部占位，互不相扰）。
- `docs/spec/diagnostics.toml`：docs/README.md 命名约定增补为豁免结构文件（固定名、无中文配对、仅英文）。

## 决策 7：提升力学——章节逐字合并，注册表直接编辑

章节增量（9900 ADDED、0100 MODIFIED）仍走"逐字合并"规则；注册表是数据文件，在变更任务中直接编辑，diff 由 code-review 审查（非合并力学）。条目模式**加字段**向后兼容、**删字段/改名**禁止——注册表本身是稳定性承诺表面，其模式的演进与码位演进同级对待。

## 决策 8：本变更自举

本变更自己的实现即受新检查约束：12 个条目落地后，第 1 章（及未来章节）文本中全部 `EXXXX:` 用法须逐码命中条目——validate.py 新检查对本仓库当前状态的通过，就是"检查器正确 + 注册表完备"的双重证明；另以负向测试（临时注入 `E9999:` 用法与 W 同号条目，验证 FAIL 后还原）证明检查器真的会拦。
