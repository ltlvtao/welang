# Design: sum-types

## 决策

- **D1 章节架构：新章 0900-sum-types + ch4 配对修订，穷尽性归 ch4。** sum 声明/构造/值类别/Never 落新章（类型侧权威）；穷尽性、臂一致、变体模式入集落 ch4（match 侧行为权威）。理由：ch4 的 Match 诊断段位 Requirement（现行 110 行）已预授权「exhaustiveness, guard coverage, arm agreement」进 E0300–E0399——注册表条目的 requirement 字段必须解析到 owner（0400-match）文件内的 Requirement，穷尽性规则落 ch4 是对既有承诺的字面兑现，无需触碰段位承诺本身。
- **D2 关键字 `type`（裁决 1）。** v0.8 原案；未来类型别名可同关键字复用（`type Name = ExistingType` 无变体形），一词两形（Zig/Gleam 先例）。破坏性（`type` 从标识符变保留字）走 ch1 预授权机制如实记录。
- **D3 仅位置载荷（裁决 2）。** `Circle(Float64)`、`None`；要命名字段装 record：`Moved(Point)`。与元组 ≤8、record 命名字段的既有分工一致。v0.8 §11 的具名载荷形式（`Circle(radius: Float64)`）不继承——偏差披露：具名载荷是匿名 record 的重复发明，构造与模式各需一套具名文法，P2 代价不成比例。
- **D4 无首个 `|` 前缀；跨行声明尾随分隔符。** 文法为 `type Name = V1 | V2 | ... Vn`，首变体前无 `|`。跨行遵循 ch2 续行集：行尾 `=` 或 `|` 续行；v0.8 的行首 `|` 排版（前一行以 `)` 结束→已到边界，新行以 `|` 起始→不能起始语句）落入既有 `E0102` 干净拒绝。起草期发现的真实文法交互：ch2 续行集是闭集，本片零新增即容纳跨行声明。
- **D5 兜底通配符仅 `_`（裁决 3）。** 维持 ch4 既有裁决：`_exh_ignore` 不复活。对 sum 而言 `_` 兜底就是明确的让步声明（否则必须列全变体），对基础类型 `_` 是唯一选择；v0.8 双通配符的意图区分由「穷尽性检查本身」承担。
- **D6 不可达臂错误级 `E0307`（裁决 4）。** 通配后之臂、变体重复列出=必然笔误或死代码，静态可判定，按 P6 绝不静默报错。v0.8 无此检查（首中即胜、后臂静默不可达）——有意加严，偏差披露。
- **D7 Never 不入基础类型清单。** ch7 清单保持 13 项；Never 与 `()` 同等对待——各有其章、自持其类（ch9 底类型 / ch8 unit 类型），清单只收「以字面量 enumerable」的类型。v0.8 §9 表把 Never 列入基础类型——不继承，偏差披露。
- **D8 Never 的一致豁免是显式例外。** ch7 R3 预写「未来任何隐式转换=需独立变更的规范层例外」——本片以 ch9 显式条款兑现第一例：Never 表达式可出现在任何类型一致位置（它永不产出值）。单一权威落 ch9，ch7 零改动。
- **D9 变体模式 refutable→仅 match。** 绑定语句名字位只收 irrefutable 模式（标识符/元组模式），变体模式在 `let` 位置按 ch2 `E0105` 拒绝。不引入 `if let`/`let else`（否决记录，非延后承诺——若未来需要独立变更提出）。
- **D10 裸载荷变体名拒绝 `E0704`。** 函数值化构造器归函数类型片裁决；在此之前 `Circle` 单独作值=未附带载荷的构造器使用，显式报错而非留白。
- **D11 sum 的所有权类别：gc 默认 / byval value；byres 与 newtype 不适用。** 资源有身份，变体集合不是资源句柄；newtype 是单底层类型包装。ch8 R1（「每个复合类型恰属四类别之一」）零修改即容纳——sum 在其类别空间内取值。
- **D12 大小写词法切分消除裸模式歧义。** 变体名 PascalCase（E0011）、绑定名 camelCase（E0012）→ 裸 PascalCase 模式恒为变体引用、恒非绑定。无需类型导向的模式解析，P1 局部可判定。
- **D13 or-模式绑定类型一致落 `E0501`。** ch4 原文「types 章批准」悬置自 ch8（元组或模式已可触发同名异型）——本片以「同名必同型，违者 E0501」落地，零新码（类型一致总纲复用）。
- **D14 ch4/ch7 示例节刷新（实现期任务，披露）。** 两章示例节的 pending 注释（「变体模式待配对修订」「Never/() 待到达」）在本片落地后失真；示例节非权威、不入增量，实现期随双语宿主一并刷新并在实现审查记录披露。
- **D15 布尔不做穷尽特例。** 基础类型（含 `Bool`）一律不可穷尽、须 `_` 兜底——v0.8 总览表原样继承；`true`/`false` 两臂穷尽 Bool 的特例（Rust 式）不做：穷尽性=「类型枚举其值」的单一判据，字面量不构成枚举。

## 备选方案（已否决）

- **enum/sum 关键字**：裁决 1 否决。enum 传统但把更通用的 `type` 留作别名的第二机制；sum 直白但无生态先例。
- **具名载荷 / 位置+具名并行**：裁决 2 否决（P2；record 已命名字段）。
- **复活 `_exh_ignore`**：裁决 3 否决（两套通配符、推翻 ch4 既有裁决）。
- **不可达臂警告级/不检查**：裁决 4 否决（与全错误级现状不一致 / 放过笔误）。
- **Never 入基础清单（13→14）**：D7 否决（无字面量、无值、无运算——清单纯度）。
- **穷尽性规则整章落 ch9 + 新 E07xx**：D1 否决（违背 ch4 段位承诺的字面预留）。
- **类型导向模式解析**（scrutinee 类型决定裸名含义）：D12 否决（大小写词法切分已足够，类型导向解析破坏 P1 局部可判定）。
- **开放 sum / Dyn 替代**：v0.8 §11.1 立场继承——封闭穷尽 vs 开放扩展二分，开放侧归接口+泛型片的 `Dyn`，不新增第三条路。
- **`if let` / `let else` 随片引入**：D9 否决（范围蔓延；refutable 绑定走 match 单通道）。
