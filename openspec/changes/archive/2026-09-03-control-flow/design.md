# Design: control-flow

## 决策

**D1 — defer 继承 v0.8（用户裁决，推翻推荐的块作用域）。**
仅函数体顶层直接项、函数退出（含提前 return/break）LIFO。块作用域方案（与块表达式正交、P1 更局部）被否——用户择简：单一退出点语义。实现约束："函数体"由声明章节批准，本章规则带前向引用；当前可触发的只有拒绝侧（嵌套块 E0204、非块体 E0203）。defer 不承担 resource 保证（resource 章节的 scope resource 是正式机制——继承 v0.8 定位）；effect 与 `?` 不因 defer 豁免（各章前向引用）。

**D2 — 裸 break/continue，循环是语句（用户裁决，同推荐）。**
loop/while 无值；break/continue 无携值、无标签（闭集）。循环产出值的唯一路径 = 显式状态（累加器 var）或后续 if/match/迭代组合子——P2/P5 对齐：break 携值是隐性的控制流数据通道。加标签 = 未来 spec change（Scenario 显式声明未批准，防"标签已被默许"的误读）。

**D3 — if 双形（继承 v0.8 §21.2，去类型化）。**
`if cond block`（无值）/ `if cond block else arm`（值 = 所取分支的块值，按第 2 章块值规则）；else-if 链 = else 臂持一个嵌套 if（链即嵌套，无独立产生式）。条件括号无特殊地位——`(c)` 是第 2 章分组，不是第二种 if 语法。分支独立作用域继承（v0.8 规则 2）；**v0.8 规则 1（编译器内部 `_ifResult0` 结果变量命名）判定为实现细节，不进规范**。E0202 覆盖"无值形式用于取值位置"这一类（if-无-else、while、loop、defer 通用），一码一义按类定义。

**D4 — defer 体唯一块形式（P2）。**
v0.8 §24 规范文本是块形式（`defer { ... }`），但其后文散见 `defer f.Release()` 非块用例——基线自不一致。从头裁决取块形式唯一（E0203 拒绝非块）；需要多语句或精确排序时块形式本就足够，需要单表达式时 `defer { cleanup() }` 一行即可。

**D5 — 段位机制：E0200–E0299 认领 + E0300–E9999 收窄。**
E01xx 段 owner 是 0200-grammar，条目 `requirement` 须在 owner 文件内解析（validate 机械约束）——本章触发 Requirement 在第 3 章，故必须新段。注册表动作：新增 `E0200-E0299`（owner 0300-control-flow）；原 `E0200-E9999` unclaimed 行收窄为 `E0300-E9999`——收窄不违反稳定性（无条目受影响，unclaimed 行是段位数据）。段内结构遵循两章先例：E0200 段头预留，E0201–E0204 连续分配，E0205–E0299 预留注释。

**D6 — 第 2 章 Statements MODIFIED（封闭枚举的增量结构）。**
原文"三种语句形式"是封闭枚举，控制流语句进入后即失真。MODIFIED 为"语句族按归属章节批准，族集合与成员按章封闭，增长只经归属章节的 spec change"——单一权威保持：语句族的准入结构定义在第 2 章，各族成员定义在各归属章节。新增 Scenario"A statement family grows"锚定增长语义。

**D7 — 类型化前向引用模式。**
条件须 Bool、分支类型一致（Never 除外）、return/Never 交互——全部归类型章节；本章以"typing is ratified by the types chapter"句式声明义务边界。与第 2 章"块值类型化归类型章节"同一模式，避免在类型系统批准前预定义类型。

**D8 — return 只批准形式。**
`return` / `return expr` 两形；fn 体内合法性、返回类型一致、Never 交互归声明/类型章节。当前无 fn 产生式，return 的正向用例依赖声明章节落地——与 defer 同一前向引用结构。

**D9 — 示例节推广为内容章节通例（用户偏好 2026-09-03）。**
第 2 章的 `## Examples (non-authoritative)` 机制（自带免责、只用已批准表面、提升时逐字并入、zh 镜像）推广到内容章节。本章示例约束：defer 正向用例需 fn 表面——以注释标注"函数表面随声明章节到来"（第 2 章 `Int64` 注释先例），或用拒绝侧示例。

## 备选方案

- **defer 块作用域**：拒（用户裁决）——正交性论点不敌单一退出点的简明性。
- **break 携值 / loop 表达式**：拒（用户裁决）——隐性数据通道，P5 压力；与 while 不对称。
- **if-else 类型一致在本章批准**：拒——类型系统未建，前向引用（D7）是唯一不自陷的路径。
- **E02xx 并入 E01xx 段**：机械不可行（D5）——owner 文件解析约束。
- **defer 允许表达式体**：拒（D4）——v0.8 自不一致，P2 取一。
