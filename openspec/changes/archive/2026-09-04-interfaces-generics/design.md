# Design: interfaces-generics

本变更的设计决策记录。裁决项（用户 2026-09-04 四项裁定）标【裁决】；v0.8 参考材料（`refr/spec-0.8.md` §12–§20，非权威）的取舍逐条注明。

## D1: 单章合一——第 10 章「Interfaces and generics」（`1000-interfaces.md`，段位 E0800–E0899）

接口与泛型在产生式上是一张网：泛型 impl（`impl<T> I for Head<T> where ...`）一条产生式横跨两题；接口声明自带泛型子句；where 约束的 bound 指名接口。拆两章会迫使同一变更内后章修订前章（或前章前向引用后章自己的声明语法）。合一章后：网内自洽，示例可用第 1–10 章全部形式。

段位数学闭合：文件前缀−200 = 段位（0600→E04xx … 0900→E07xx），第 10 章 1000 → E0800–E0899，恰好把未认领段从 E0800–E9999 收窄为单一区间 E0900–E9999，无需引入两个未认领段。

**备选（拒）**：两章 1000-interfaces + 1100-generics（段位 E1000–E1099）——需同变更跨章修订；未认领段裂成 E0800–E0999 与 E1100–E9999 两段。

## D2: `self` 非关键字——裸首参数产生式 + 拼写强制（E0802）【取舍】

接收者是方法签名的第一个参数，裸写（无类型标注），两种形式 `self` / `mut self`；类型由 impl 头固定。`self` 不是关键字（第 1 章零软关键字义务不受扰）：它是普通 camelCase 绑定。拼写按第 1 章命名约定的强制模型执行——接收者必须拼作 `self`（E0802），如同类型名必须 PascalCase（E0011）。这保持方法体全语言统一可读，且 `self` 在其他位置仍是合法标识符。

**备选（拒）**：把 `self` 升为完整关键字——合法（零**软**关键字不禁止新增硬关键字），但为一个位置用途付出全局保留词，且 v0.8 亦未保留。允许任意接收者名（`me`）——破坏统一性，与 ch1 强制约定精神相悖。

## D3: `mut` 用初始关键字表的预留位

`mut` 自第 1 章初始表即保留、至今无用。`mut self` 恰好兑付该预留——本变更不为其动关键字表（ch1 增补说明句记录此事）。

## D4: `Dyn` 是普通类型名，非关键字

与基础类型名同型：标准作用域的 PascalCase 名。`Dyn<Interface>` 是类型引用形式（ch7 修订收编），`Dyn` 本身可被模块系统规则处理名字冲突（与 Int64 等同归模块系统章）。

**备选（拒）**：`Dyn` 关键字化——基础类型名皆非关键字，单独例外无理。

## D5: `derives` 新关键字 + 尾随子句【取舍】

`record Name { ... } derives Eq, Hash`、`newtype Name(T) derives Eq`、`type Name = ... derives Eq`——子句尾随声明最后一个 token，必须与闭 `}` 或末变体同行（行接续规则的自然推论：完整声明行末是边界，下一行以 `derives` 起头不合任何产生式，E0105）。第 1 章关键字表 +4（interface impl where derives，25→29 词），破坏性变更依例记录。

**备选（拒）**：`#[derives(...)]` 属性形式——把语法藏进属性单元，与「属性是编译期字面量标注」的既有定位不符；v0.8 亦用关键字。

## D6: 变异通道——`self.field = expr` 仅限 mut self 体内【裁决】

gc 原地变更、byres 允许、byval 禁 `mut self`（E0812）。第 8 章「全语言无字段赋值」句修订为指向本唯一例外（Field access MODIFIED），ch2 赋值族同步开此一目。方法体外一切字段赋值仍 E0105；`u.name = e` 永不合法——目标产生式字面就是 `self.field`。

补落一条必要语义（裁决的推论）：**mut self 方法经不可变绑定可调用**——绑定的不可变管重绑定、不管对象状态；写在共享值上原地生效。否则 `let c = Counter{...}; c.bump()` 永不成立，裁决通道形同虚设。

## D7: 关联类型全套 v0.8 规则【裁决】

上限 4（E0803）、声明无上界（E0804）、impl 绑定先于方法（E0805/E0806）、绑定 RHS 为类型引用（允许 impl 自身泛型参数）、禁 Dyn 装箱（E0819）、where 等式约束 RHS 必须具体（E0831）。v0.8 的 E0280–E0284 语义按新码位重排，号码不继承。

## D8: derives 目标集 Eq/Hash/Show；`==` 仅基础类型【裁决】

`Eq`→`.equals(other: Self) -> Bool`、`Hash`→`.hash() -> Int64`、`Show`→`.toDebugString() -> String`；生成方法与手写方法同等入成员解析。`==` 保持第 7 章「仅基础类型」；组合类型相等一律 `.equals()`；手写 `impl Eq for` 禁止（E0822）。Eq/Hash 要求逐字段（载荷/底层）递归具备——基础类型天然具备、组合类型经自身 derives 具备，否则 E0823；泛型声明的该检查延至实例化处。Encodable/Decodable 延后 JSON 变更、Shareable 归并发章（非目标，指针句已留）。

## D9: Dyn 构造仅显式 `Dyn<Interface>(expr)`【裁决】

单一形式零推断；v0.8 的上下文推断 `Dyn(expr)` 与 E0722 歧义诊断不继承。关联类型接口禁装箱（E0819）；非接口实参（含 `Dyn<T>`）E0820；裸接口名占类型槽 E0821（接口仅以 `Dyn<I>` 占类型槽）。

## D10: 无型变、无子类型（长期）

无型变标注位、无型变关键字。impl 是能力不是继承：实现 I 不使 T 可出现在期望 I / Dyn<I> / 异实例化泛型处（E0501）。擦除路由 = `Dyn<I>`，参数化路由 = 带界参数。record/sum 名义封闭。

## D11: 孤儿规则；扩展方法否决

impl 合法当且仅当接口或头类型声明于本模块（E0810，含固有 impl：头类型必须本地）。对外来类型的扩展——本地接口实现之是唯一路由（v0.8 立场：**否决**扩展方法，非延后，长期）。

## D12: 无运算符重载（长期）

运算符表（ch1）与运算符语义（ch7）封闭；运算符 token 永非方法名（E0105）。组合相等 = 生成 `.equals()`；组合算术/索引（若有）= 具名方法 `.add()`/`.at()`。v0.8 §12.6 立场照立。

## D13: 推断模型——实参统一 + 显式形式，无期望类型推断

泛型调用/构造的类型实参恰由两途确定：实参表达式类型与标注参数类型（构造处：字段/载荷表达式与声明类型）统一；或显式形式（fn 调用 `name<T...>(args)`、newtype/变体构造 `Name<T...>(args)`、record 构造/更新头 `Name<T...> { ... }`）。期望类型不参与推断——未定即 E0827，修复 = 显式形式。单向、可从调用自身文本判定（P1 局部可判定）。与 D9 同一裁决精神：单一形式零上下文。

**备选（拒）**：期望类型/双向推断——引入调用点不可本地判定的形，E0722 式歧义诊断随之而来。

## D14: 关联类型等式约束 RHS 具体型

`T.Element == Concrete`：RHS 须基础/名义/其泛型应用；`== U`、`== T` 拒绝（E0831）。等式成立后声明内 `T.Element` 即该具体类型。v0.8 §12.1 立场。

## D15: 固有方法与继承默认方法同名 → E0814（收紧 v0.8）

v0.8 规则：固有优先于默认，静默选择。本规范改为拒绝（E0814）：一体两名一体两体。修复 = 在 for-form impl 里显式定义该方法（这就是覆写）。静默优先违反「一体一名」（Member name resolution）的既有纪律，故收紧，如此记录。

## D16: 接口名非值类型

`Describable` 不是值的类型：类型槽中接口仅以 `Dyn<Describable>` 出现（E0821）。杜绝「接口当超类型用」的暗道（与 D10 互锁）。

## D17: 嵌套泛型闭括号分离——兑现 ch1 指针

ch1 运算符表早已注明「与嵌套泛型闭括号的交互（需分隔）由泛型章规定」。兑现：`Box<Box<Int64>>` 中 `>>` 按最大吞噬是移位 token，槽被拒（E0105，修复 `Box<Box<Int64> >`）。不设新码——词法即如此，错误在解析位。

## D18: 泛型字段/载荷的类别与派生检查在实例化处

`byval record Box<T> { value: T }` 声明处无法验证 T 的类别诚实——检查落在每次实例化（E0601/E0702 复用，不新码）；derives 的字段要求同理（E0823 在实例化处）。声明的参数化与使用的检查分离，与值 record 镜像规则的语义一致。

## D19: 方法可见性

impl 块本身无 `pub`；impl 内方法定义可带 `pub`（跨模块可达），缺省模块局部。for-form impl 方法的 `pub` 只管直名可达——经接口分发时随接口可达性。接口成员不写可见性：成员可达性 = 接口可达性。v0.8 未述，此为最小一致补全（对齐 ch6 pub 模型）。

## D20: 延后项（非否决）

泛型方法（含 `obj.name<T>(args)` 显式形式）——无 v0.8 依据，连带 E0826 的可触发面一起延后（规则先批，面到即生效，见 Generic parameter declarations 的元场景）；接口级 where 子句；泛型 newtype。

## D21: 「未知成员」诊断归位 E0816，ch8 E0604 收窄

成员解析是本章一条规则：未知成员访问（含 `self.field = e` 的未知字段）统一 E0816。ch8 的「record 无此字段」场景（`u.email`）随 Field access MODIFIED 迁至 E0816；E0604 触发面收窄为构造/更新的字段集不匹配。一类错误一个码，跨章引用而非复制。

## D22: 默认方法体内 `self` 的静态位置 = 接口

默认体不知具体类型：成员候选 = 接口方法集（E0815 之外），字段永不在集内。经 `self` 调用接口其他方法晚绑定（impl 有定义走 impl，否则走默认）。与 Dyn 值的成员解析同一形状，同一码。

## 拒绝方案汇总

- 两章拆分（D1）
- `self` 关键字化 / 任意接收者名（D2）
- 上下文推断 `Dyn(expr)` 与 E0722（D9，裁决否决）
- 扩展方法（D11，v0.8 否决，长期）
- 运算符重载（D12，长期）
- `#[derives]` 属性形式（D5）
- 手写 `impl Eq`（D8）
- 期望类型/双向推断（D13）
- `Self` 类型——具体 impl 头已知，无需自指
- 型变标注（D10）
- impl 块 `pub`（D19）
- v0.8 诊断码号继承（E0280 系/E0320 系等）——一律新段位重排，旧号不复用
