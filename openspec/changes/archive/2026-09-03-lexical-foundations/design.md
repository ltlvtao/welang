# Design: lexical-foundations

## 决策 1：零软关键字（用户裁决 2026-09-03）

原则 4 预留的"词法例外"条款兑现为**空集且封闭**：v0.8 §2 引用 §5 的软关键字机制从未存在（悬空引用），本变更以显式裁决终结它——不是修复引用，而是取消例外。理由：任何上下文相关词法都会让 token 类型依赖语法位置，破坏"给定字节流，token 序列唯一确定"的可判定性（P4/P6），也破坏工具（格式化器、LSP、语法高亮）的无状态处理。代价：关键字不可作标识符——新语言无历史包袱，接受。

## 决策 2：标识符仅 ASCII（用户裁决 2026-09-03）

`[A-Za-z_][A-Za-z0-9_]*`。拒绝 Unicode 标识符的三个理由：同形字符攻击（西里尔 а vs 拉丁 a）是安全面而非风格面；NFC 归一化使一个标识符存在多种拼写（é 单码位 vs e+组合符），直接违反 P4"两种合理解释必须拒绝"；confusable 检测是常驻算法负担（P3 气味）。中文自由用于注释与字符串——字符集限制只针对标识符。被拒替代：XID_Start/XID_Continue + NFC 归一化 + confusable 黑名单（Swift/Rust 路线）。

## 决策 3：初始关键字清单 = "确定性下限"策略（21 词）

清单只收录**语法已被或必然被某章批准**的词：声明核心（`fn let var pub import as mut`）、控制流（`if else return match for in while loop break continue defer`）、字面量（`true false`——v0.8 的 56 词清单**没有** true/false，它们实为 prelude 标识符可被遮蔽，本变更为终结此歧义将其收为关键字）、FFI（`foreign`——第 0 章已批准 `foreign "c"`）。

被拒替代：**急切全量预留**（把 v0.8 的 56 词一次性收编）。拒绝理由：其中近半绑定于未裁决特性（`mock`、`timeout`、`test_each`、`for_all`、`byval`、`open`、`guard`、`collectAll`……），特性若在重裁决中消亡则留下永不回收的死关键字，污染标识符空间；P10 纪律下"为不存在的语法保留单词"与半成品特性同罪。代价：后续章节新增关键字可能破坏既有代码中的同名标识符——1.0 前接受，且新增必须走 spec 变更（增量里已写成义务）。

## 决策 4：字面量形态（v0.8 基线 + 三处新裁决）

继承 v0.8（§9）：后缀体系 `i8..u64`/`f32`/`f64`、后缀紧贴末位数字、`'x'` 单引号 rune、`"..."` 字符串。新裁决三处：

1. **进制前缀**：v0.8 未见十六/八/二进制字面量，后端语言（协议、位标志）确需——增补 `0x`/`0o`/`0b`，十进制禁前导零（`0` 本身合法），与后缀体系正交。
2. **数字分隔符 `_` 仅在两数字之间**（`1_000` 合法，`1__0`/`_100`/`100_`/`0x_FF`/`100_i64` 非法）：机械规则、无例外，P4 形态。
3. **无后缀字面量的默认类型不在此定**（v0.8 定为 Int64/Float64）——默认类型绑定是类型系统决定，留给类型章节；本章只锁形态。

被拒替代：原始字符串/多行字符串（v0.8 无）——正则、JSON 场景确有痛感，但每加一种字符串形态就是一条新的词法路径（P2），推迟到标准库字符串章节显式裁决；段内预留码位（见决策 8）预留给此类增补。

## 决策 5：转义集闭集枚举

`\n \t \r \0 \\ \" \' \u{h..}`（1–6 位十六进制，≤ U+10FFFF，禁代理项）。拒绝 `\x41`、`\e` 等：闭集之外一律 `E0005`。理由：每个转义都是一条词法规则，闭集 + 拒绝未知 = P4；`\u{}` 覆盖 `\x` 的全部用途且无长度歧义。

## 决策 6：注释不嵌套

`/* */` 首个 `*/` 闭合、内层 `/*` 为普通文本（机械规则）。被拒替代：嵌套块注释（`/* /* */ */`）——需要计数器状态机，收益（注释掉含注释的代码段）可由行注释逐行达成；"注释掉大段代码"在 AI 原生流程里本就该删除而非注释。`///` 文档注释只定形态，附体规则归声明章节。

## 决策 7：命名约定为错误级（E0011–E0013）

继承 v0.8 §4 的四条约定（PascalCase/camelCase/小写模块/常量随变量——不用 SCREAMING_CASE），但把级别问题显式裁决为**错误**：单一约定是 P2/P7（单一书写路径、单一表面）的组成部分，警告级会立即造成"两种合法拼写"。被拒替代：警告级 + fmt 自动改名——fmt 改名是语义变更（触及引用），不属于格式化器职责。

## 决策 8：诊断码分段表入本章，作为唯一注册表

`E/W + 4 位数字`。分段：E0001–E0099 词法与命名（本章）、E0100–E0199 语法（下一章）、E0200+ 由各章认领。**v0.8 的码位编号不继承**（其注册表从未随任何发布物交付，无兼容负担；本变更是注册表第一刀）——包括不保留其编号习惯：评审中废弃了初稿的 E0021（v0.8 式跳号），规范为段内连续分配。段内结构：**E0001–E0009 token 级错误**（invalid character / unterminated string / unterminated rune / unterminated comment / invalid escape / invalid numeric / unbalanced interpolation / unknown attribute / non-literal attribute argument）、**E0010 边界预留**、**E0011–E0019 命名块**（E0011–E0013 分配，E0014–E0019 预留）、**E0020–E0099 段内开放区**。每码一义、全局唯一、重编号禁止——第 0 章"诊断协议是稳定性承诺"从此有第一个可引用的注册表。

## 决策 9：`<<`/`>>` 单 token + 泛型闭合留白

最大吞噬下 `>>` 是移位单 token；嵌套泛型右尖括号的分隔要求（`> >` 或等价机制）**留给泛型章节**显式规定，本章只声明交互的存在。被拒替代：词法层拆分 `>` 永不组合（Rust 路线）——它使 `>>` 的 token 化依赖语法上下文，违反决策 1 的无上下文词法；也拒绝要求泛型用 `[]` 包裹（Swift 路线）——留待泛型章节整体裁决，此处不预设立场。

## 决策 10：提升与校验

归档时 ADDED Requirements 逐字合并为 `docs/spec/0100-lexical.md`（第二个章节文件，步长 100 首次实际使用）+ 配对翻译 `0100-lexical.zh.md`；术语对照表在 0000 章表基础上增补（token / keyword / literal / escape / maximal munch / interpolation / attribute / segment 等约 12 条）。校验：validate + docs_sync + 规范一致性复核（诊断码唯一性——本章自带分段表即注册表；§ 交叉引用有效；术语一致）。
