# Proposal: lexical-foundations

## Why

1. **规范有了宪法，没有内容。** `docs/spec/0000-principles.md` 批准了裁决层，但整个 `docs/spec/` 尚无任何语言内容——没有任何章节定义"We 源文件是什么"。后续每一个内容章节（类型、表达式、函数……）都需要引用一个已批准的 token 清单与诊断码方案，目前无可引用之物。
2. **v0.8 的词法层带着未解决的内部矛盾。** `refr/spec-0.8.md` §2 原则 4 声明"软关键字机制（见 §5）是本规范唯一允许的上下文相关词法例外"，而 §5 标题即为"保留关键字（54 个）"，通篇没有任何软关键字机制的描述——宪法性条款引用了不存在的东西；且 §5 标题写 54 个、清单实际列出 56 个（无重复）。从头建立纪律下，词法例外问题必须显式裁决，不得带着矛盾继承。
3. **诊断协议（第 0 章：稳定性承诺）零码位分配。** E/W 编号方案需要第一次刻意的分配，后续章节在其上扩展；第一刀的分段方式决定整个注册表的形状。

## 目标与非目标

目标：

1. 创建规范第 1 章（`docs/spec/0100-lexical.md`，步长 100 编号的首次实际使用）：We 源文件的**完整词法规范**——源文件与编码、空白与换行、注释、标识符、关键字、字面量（整数/浮点/字符串/字符；布尔词法由 `true`/`false` 关键字承载）、运算符与标点（含 `#[` 属性词法单元）。
2. **裁决关键字机制**（保留字 vs 上下文关键字）并给出初始闭集清单——这是第 0 章原则 4"词法例外"条款的直接兑现：要么零例外，要么闭集枚举。
3. **裁决标识符字符集**（ASCII vs Unicode）。
4. **建立诊断码方案**：E/W 码格式与分段骨架，分配词法段的首批诊断码（非法 token、未终结字符串、非法转义、未知属性等）。
5. 命名约定诊断（v0.8 §4 的 PascalCase/camelCase/模块小写）：作为词法层可判定的诊断纳入，级别（错误 vs 警告）作为 ready 阶段主张裁决。

非目标：

- **语法结构**（块与花括号、语句与分号、表达式骨架、运算符优先级表）——紧随其后的独立变更（第 2 章 `0200-grammar`）；本变更只负责 token 层。
- **字面量的语义**（字面量的类型推断、运算符含义）——类型系统章节。
- **`we.toml` 与项目结构**（v0.8 §3）——项目/模块系统章节。
- **属性系统的语义**（白名单内容、各属性行为）——属性随其特性章节落地；本变更只定词法形态与"闭集白名单 + 不得影响检查"的约束表述。
- **格式化器行为细节**——tooling 层（第 0 章原则 7 已锁约束）。

## What Changes

- 新增规范能力 `lexical`，全部为 ADDED Requirements（11 条），归档提升为 `docs/spec/0100-lexical.md`。Requirement 清单：Source files / Token model / Identifiers / Keywords / Numeric literals / String and rune literals / Operators and punctuation / Comments / Attribute lexical unit / Naming conventions / Diagnostic code scheme。
- 首次分配诊断码：E（错误）与 W（警告）格式定义、段位骨架、词法段与命名段的首批码。
- 初始关键字闭集清单（裁决后定稿）与"新增关键字 = spec 层变更"的闭集规则。

## 影响层

- **spec**：`docs/spec/` 第二个章节文件（0100），此后所有内容章节引用其 token 清单与诊断码方案。
- 不触及 process / docs 机制（双语配对属既有约定，随变更完成）。

## 影响范围

- **所有后续内容章节**：token 与诊断码从本章节引用；新增关键字/运算符/字面量形态均以本章节闭集规则的 MODIFIED 增量进入。
- **与 v0.8 的关系**：§4–§7 与 §7.1 作为候选素材逐条重新裁决；§2/§5 的软关键字悬空矛盾、§5 的 54/56 计数错误由本变更的显式裁决终结。
- **不受影响**：流程机制、工具链代码（尚不存在）、既有两章内容（0000 不修改）。
- **风险与不可逆性**：关键字闭集与标识符字符集是 1.0 前可调、1.0 后极难反转的语言表面决定；诊断码分段方案一旦有章节跟进引用即成稳定性承诺的一部分。

4. **原则一致性** ✅ 且为本章主角：原则 4 的"词法例外"条款在此兑现——裁决为**零软关键字**（例外集为空且封闭，用户裁决 2026-09-03）；标识符**仅 ASCII**（用户裁决 2026-09-03）消除同形字符与归一化二义性（P4/P3）；闭集规则（关键字、运算符、转义、属性白名单四处闭集）直接落实 P4/P8。
5. **参考基线固定** ✅ refr 引用固定为：§4（标识符与命名）、§5（关键字清单，含 54/56 计数错误）、§6（运算符与标点）、§7/§7.1（注释与属性）、§9/§9.1（基础类型与字面量、插值）、§22（运算符）、§24（defer 形态）。v0.8 的诊断码编号**不继承**（其注册表从未发布，无兼容负担；本变更是注册表的第一刀）。
6. **验收边界** ✅ 目标可机械判定：章节文件存在、Requirement/Scenario 齐备、首批诊断码在增量中逐一登记、关键字清单与字符集规则成文；非目标五项（语法结构、字面量语义、we.toml、属性语义、格式化器）显式排除。
7. **粒度** ✅ 单一关注点"token 层完整规范"。与 0200 语法骨架的切分依据：词法可独立垂直验收（给定任意字节流，token 序列与词法诊断完全确定），语法不能（依赖各特性章节的产生式）。

裁决核销：关键字机制（全保留字零软关键字）与标识符字符集（仅 ASCII）已于 2026-09-03 经用户裁决；初始关键字清单策略（21 词确定性下限）与命名约定诊断级别（错误级 E0011–E0013）亦于 2026-09-03 经用户裁决确认；其余次要定位（字面量细节、无原始字符串、注释不嵌套、诊断码分段）在 spec 增量与 design 中给出主张，随 `welang-change-review` 一并裁决。
