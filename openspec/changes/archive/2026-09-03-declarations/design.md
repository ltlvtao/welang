# Design: declarations

## D1 · 体值对称：末项表达式即隐式返回值

函数体是 ch2 块，块值规则不为此新设机制：声明了返回类型的函数，其体块值就是返回值（末项表达式 = 隐式返回），`return expr` 是提前退出的等价物。单一返回机制（块值 + 显式 return），无双轨。路径完备性（每条路径都产出值）是流分析 → 类型章节。

## D2 · 无返回值函数：隐式丢弃（裁决 1）

形式层不设卡。真正值得报错的情形——丢弃了非 unit 的实值——需要 unit 类型才可判定，随类型章节成对修订（与 match 穷尽性延后同构：一个分析路径，而非先设一个较弱的句法层替身）。ch2 的显式丢弃（`let _ =`）仍管块绑定位置，不受影响。

## D3 · 顶层 var 拒绝（裁决 2）

继承 v0.8 §46。模块级可变状态是并发与推理的双重陷阱；`var` 仅块内合法。E0403 只在顶层位置触发，块内 `var` 不受影响。

## D4 · import 两形（裁决 3）

`import path` 与 `import path as 别名`，各引入恰一个名字（末段或别名）。选择性导入与通缀不批准：名字来源恒一处可读（P2 + 局部可判定）。别名与路径同受 ch1 模块命名约束（E0013）。

## D5 · 注解严格度（裁决 4）

参数 `name: type` 强制——参数无推断（P1）。裸参数名不适配任何产生式 → 复用 E0105（消息具名 `name: type` 产生式），不设新码。返回类型可省，省略即声明不产出值；配一条形式层规则堵住矛盾写法：无返回值函数里 `return expr` → E0402。注解槽的文法随 ch2 先例前向引用类型章节。

## D6 · return 位置：E0401 覆盖顶层与 defer 体

顶层 return 显然非法。defer 体内的 return 单独裁定为非法：defer 体在函数退出时执行，彼时已无存活控制流可退出——合法化它等于发明时间旅行。两处共用 E0401（同一语义：return 不在函数体控制流中），条目 description 明示两种位置。

## D7 · 模块内一个名字空间

fn 名、顶层 let 名、import 引入名共享一个名字空间（E0404）。顶层与块内局部的遮蔽关系延后：那是绑定作用域问题，类型/名字解析章节批准（本章只在 R7 陈述边界）。

## D8 · 文档注释附着：位置性，空行不断链

连续 `///` 行成一个文档单元，附着下一个顶层项；空行与普通注释不断链（附着只看下一个项，机械可判定）。孤儿单元（文件内再无顶层项）→ E0405。文档内容的语义与渲染归工具链章节。

## D9 · 零宿主修订

首次纯 ADDITIVE 内容章节。四处前向引用（ch1 文档注释、ch1 属性"next declaration"、ch3 return 语境、ch3 defer 函数体）在本章落地后自然消解，宿主文本零改动。这是前向引用纪律的第一次全额兑现，也是对"引用必须可解析"约定的正向验证。

## D10 · 初始化语义只定模块内源序

顶层 let 初始化子在模块初始化时按源序求值（模块内可判定）；跨模块初始化模型（依赖序、失败语义）归模块系统章节。避免在本章预设运行时布局。

## D11 · 段位认领与 E0401 的注脚

认领 E0400–E0499（owner 0600-declarations），分配 E0401–E0405（return 位置、无值返回值、顶层 var、重名、孤儿文档）；E0406–E0499 预留给本章修订。未认领段收窄为 E0500–E9999。注脚：for-iteration 的注册表注入哨兵恰用了 E0401（从未注册、已还原）——该码首次真实分配即在本章。

## 备选方案（被拒）

- **严格体末丢弃检查**（无返回值函数末项不得为表达式）：与块值哲学完全一致，但几乎每个无返回值函数末尾都是调用，`let _ =` 将遍地——噪音压倒收益，被拒（裁决 1 取隐式丢弃）。
- **返回类型强制**：签名完全自描述，但无返回值函数占大头，噪音字段常在——被拒（裁决 4）。
- **选择性导入 `import a.{b, c}`**：少打几个字，代价是两套名字引入规则与遮蔽面翻倍——被拒（裁决 3）。
- **本章一并批准模块解析算法**：需要项目结构/we.toml/toolchain 边界，耦合过宽——拆至模块系统章节（非目标 1、2、8）。
- **允许顶层 var**：v0.8 已拒绝，维持（裁决 2）。
- **defer 体内合法化 return**：见 D6，语义上不可定义。
