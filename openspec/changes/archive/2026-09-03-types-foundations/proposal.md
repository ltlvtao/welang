# Proposal: types-foundations

## Why

1. 类型欠账已到偿还线：ch1「unsuffixed literal 的类型由类型章节定义」、ch2「块值类型化由类型章节批准」、ch3「条件类型化前向引用类型章节」、ch4「守卫类型化→类型章节」、ch6「注解槽的类型文法由类型章节批准」——五处前向引用等待本章。字面量默认、注解合法性、条件合法性至今全部悬空。
2. v0.8 素材固定：§9 基础类型表（Int8–UInt64、Float32/64、Bool、String、Bytes、Rune）+ 整数溢出检查语义 + 无后缀默认（Int64/Float64）+ 全面无隐式转换（混合报错、显式方法转换）。
3. 类型大章已裁定为六片序列（基础→复合+所有权→sum+match 修订→接口+泛型→可迭代协议→函数类型+闭包），本片是第一片：无依赖、纯增量，为后续五片立地基。

## 目标与非目标

目标：

1. 建第 7 章 `docs/spec/0700-types.md`（+zh 孪生）：基础类型清单、字面量类型化、无隐式转换、整数溢出语义、类型引用文法（注解槽的填充物）、条件位置 Bool、块值类型化。
2. 注册表：认领段位 E0500–E0599（owner 0700-types），分配 E0501–E0503 三码；未认领段收窄为 E0600–E9999。
3. 兑现五处前向引用（ch1 字面量默认、ch2 块值、ch3 条件、ch4 守卫、ch6 注解文法），零宿主修订。

非目标：

1. 复合类型：record（gc/byval/byres 四类所有权）、tuple、newtype、`()` Unit、函数类型 → 复合+所有权片。
2. sum 类型、变体/元组模式（ch4 成对修订）、穷尽性（E0303+）、Never 底类型 → sum 片。
3. 接口/impl/关联类型/泛型 → 接口+泛型片。
4. Iterable/Iterator 协议、Range 类型化、for 变量类型化、String 逻辑迭代产出 Rune 的协议面 → 可迭代协议片（String 迭代以 Rune 为单位这一事实随本章清单陈述，协议留待）。
5. 值级丢弃检查（需要 Unit 才可定义「非 unit 实值被丢弃」）、局部遮蔽规则 → 复合片。
6. 显式转换方法与 wrapping 方法的名字清单（`.toInt64()`、`.wrappingAdd()` 等）→ 标准库章节；本章只批准「转换必经显式方法」与「wrapping 必经显式方法」的义务。
7. 运行时溢出陷阱的构造名（panic）与捕获边界 → 错误机制章节；本章只定「永不静默回绕」。
8. 类型名解析（名字是否指向已批准类型）依赖模块解析 → 模块系统章节；本章只批文法形状。

## What Changes

1. `specs/types/spec.md`：7 条 ADDED Requirements——Base type inventory / Literal typing / No implicit conversion / Integer overflow semantics / Type references / Condition positions / Block value typing。
2. `specs/types/examples.md`：示例节（非权威，提升时逐字并入第 7 章）。
3. `docs/spec/diagnostics.toml`：段位表新增 `E0500-E0599`（owner 0700-types），未认领段收窄为 `E0600-E9999`；新增 3 条目 E0501–E0503。
4. 无宿主章节修订：五处前向引用在本章落地后自然消解。

## 影响层

## 影响范围

## 裁决记录

2026-09-03 用户裁决四项（均取推荐）：

1. **切分方案：六片**——基础（本片）→ 复合+所有权 → sum+match 修订 → 接口+泛型 → 可迭代协议 → 函数类型+闭包；每片独立完整生命周期，依赖单向。
2. **无后缀字面量默认：整数 Int64、浮点 Float64**——兑现 ch1 欠账；窄位宽与无符号经后缀显式。
3. **转换策略：全面无隐式转换**——任何跨类型混合即拒（E0501），转换必经显式方法（方法名清单归标准库章节）。
4. **整数溢出：检查语义，永不静默回绕**——编译期可判溢出 = 编译错误（E0502）；运行时溢出 = 检查陷阱（陷阱构造名归错误机制章节）；wrapping 必经显式方法。
