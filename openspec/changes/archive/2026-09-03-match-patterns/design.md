# Design: match-patterns

## D1 臂分隔：换行，无分隔符（裁决 1）

与第 2 章行接续模型同构：语句边界推断的续行集与边界规则不加修改地管臂。臂间逗号不是产生式（E0105）。代价：单行多臂不可能——接受；单臂场景本来就近乎总是多行。拒绝 v0.8 未提及、Rust 式逗号的原因：行尾逗号 = 变相分号，在唯一一处重建用户已整体拒绝的显式终止符模型（不对称，P2）。`=>` 不加入续行集（闭集不动）；跨行臂体用块体表达，`200 => {` 后块自然跨行。

## D2 `_exh_ignore` 不继承（裁决 2）

通配符仅 `_`（P2 单形式）。v0.8 的显式穷尽性豁免名在类型层落地前语义不可触发——现在批准等于挂空壳。豁免若确有需求，与穷尽性检查同期设计（非目标 1 的修订届时一并裁决）。

## D3 可达性延后（裁决 3）

死臂检测与穷尽性是同一分析的两面（`_` 之后的臂 = 穷尽后的臂）。句法级部分分析（仅 `_`/绑定/含通配或模式可判）会建第二条更弱的路径：字面量臂需类型信息才能判定，两条路径并存时"哪些臂查过"取决于查哪层——P1 单一路径受损。全部延后至类型层；E0303+ 预留。

## D4 臂体单规则：表达式（v0.8"两种形式"坍缩）

v0.8 §21.3 列"表达式体/块体"两种形式；在本仓第 2 章框架下块即表达式，`pattern => body`（body 为表达式）一条规则覆盖两者——无双形式问题（P2 无涉）。空块 `{}` 类型为 `Unit` 的说法属类型层，不在此处出现。

## D5 穷尽性整体前向引用（§21.4/§21.5 的分层归宿）

"守卫不计入穷尽性、须守卫外兜底"与"字面量类型须 `_` 兜底"都是关于证明的规则，其可判定性依赖类型信息（变体清单、scrutinee 类型）。形式层批准的只有守卫的形（`pattern if cond`）、惰性与作用域。前向引用措辞与第 3 章同式（"ratified by the types chapter"）；类型章节修订届时在本章增补 Requirement 并在 E0303–E0399 分配。

## D6 变体/元组模式：命名进入路径

模式集现封闭于五类（字面量/绑定/通配/或/守卫）。变体 `Name(args)`、元组 `(a, b)` 及嵌套解构显式延后，进入路径命名：随 sum types/元组的成对修订（类似索引语法之于集合章节）。此前一律 E0105——LLM 生成 We 代码时的变体模式会被立即拒绝并指回已批准表面形式（P1 闭集 + 可诊断）。

## D7 第 2 章表达式骨架增长规则（MODIFIED）

语句族规则（第 3 章引入）在表达式侧无对称物——第 3 章 if-as-expression 未修订骨架即入，属已披露缺口。本变更补齐："关键字引领的表达式形式按归属章节批准"（if with else → 控制流章；match → 本章），追溯性为 if 定基，并使未来形式（闭包等）有唯一进入路径。骨架的 primary/postfix/unary 层不动。match 花括号组不是第 2 章块：装臂非语句、无块值；臂界由行接续推断（D1）。

## D8 段位与段内结构

E0300–E0399 owner 0400-match（validate 检查 (d) 机械要求）；未认领收窄至 E0400–E9999。首批 E0301（零臂）、E0302（或模式绑集不一致）；E0303–E0399 预留给类型层 match 检查（穷尽性、守卫覆盖、臂一致）经修订入段。E0200–E0299 段内注释同步去 "match arms" 字样（该预留表述写于 match 归属未定时，现已过时；注释修订不触条目）。

## 备选方案（已拒）

- 逗号分隔臂（Rust 式）：见 D1，重建被拒的终止符模型。
- 继承 `_exh_ignore`：见 D2，空壳 + P2。
- 现批句法可达性错误（E0303 当即分配）：见 D3，双路径。
- 在 E0205+ 续段分配：机械不可行（检查 (d)），且段内注释权属控制流章。
- 本变更一并批准穷尽性：需变体清单与类型化，层不属此；拆分即本设计。
