# Proposal: grammar-skeleton

## Why

1. **词法层有 token，语法层无骨架。** 第 1 章批准了闭集 token 清单，但没有任何规范定义这些 token 如何组合成块、语句与表达式——`a + b * c` 的结合方式、语句如何终止、块是否有值，均无裁决。后续每个内容章节（控制流、函数、类型）都需要把产生式插进一个已批准的语法骨架，目前无可插之物。
2. **v0.8 的语法层是散点而非骨架，且带缺口。** §21.1 给出块表达式三规则（语句分号结尾；末项无分号表达式即块值；块级作用域）但从未给出运算符优先级与结合性表——v0.8 通篇无此表，解析的确定性悬空；§21.2 的 if/else 分支类型一致、`for` 的 `Iterable<T>` 约束等语义与产生式混在一处。从头裁决须先把"骨架"（块/语句/表达式/优先级/歧义拒绝）与"语义"（类型规则）分离。
3. **诊断注册表的 E0100–E0199 语法段位无人认领。** 注册表刚落地（段位 owner 标注 pending），语法骨架是其第一个认领者——本变更是新扩展义务（同一变更内扩展注册表）的首次执行。

## 目标与非目标

目标：

1. 创建规范第 2 章（`docs/spec/0200-grammar.md`）：语法**骨架**——确定性解析模型与歧义拒绝义务（P4）、块表达式与块值规则、语句与分号规则、赋值语句地位、表达式骨架（初等/后缀/一元）、运算符优先级与结合性闭集表。
2. **认领注册表语法段位** E0100–E0199 并分配首批语法诊断码（歧义拒绝、缺分号、非结合链、意外 token 等），同步扩展 `docs/spec/diagnostics.toml`（owner 由 pending 转正）。
3. 显式裁决 v0.8 缺失的优先级表：对第 1 章已批准的运算符闭集给出完整优先级与结合性，形成机械可判定的解析规范。

非目标：

- **控制流产生式与语义**（`if`/`match`/`for`/`while`/`loop`/`break`/`continue`/`return`/`defer`）——独立章节；各形式携带类型规则（如 if/else 分支类型一致），与骨架分离裁决。
- **声明产生式**（`fn`/`import`/`pub`/顶层绑定与模块顶层 `var` 禁令 E0130 类规则）——声明/模块章节。
- **类型规则**（块值类型、运算符操作数类型、`==` 需 derives Eq 等）——类型系统章节；本章只定形，不定型。
- **范围运算符 `..` 与迭代语法**——`..` 不在第 1 章闭集清单内；范围语法（词法增补 `..` token + 产生式）随迭代章节整体裁决，本章不预设。
- **λ 与函数类型语法**（`fn(...)->...`、`|x| ...`）——函数章节。

## What Changes

- 新增规范能力 `grammar`，全部为 ADDED Requirements（7 条，约 20 个 Scenarios），归档提升为 `docs/spec/0200-grammar.md`：
  1. 解析模型与歧义拒绝义务（P4；E0101）
  2. 行接续与分号推断（括号内换行不敏感 + 深度 0 尾 token 续行闭集；E0102）
  3. 块与块值（块是表达式；末项表达式即块值；`let _ =` 显式丢弃）
  4. 语句（绑定/赋值/表达式语句；赋值是语句不是表达式；E0103）
  5. 表达式骨架（初等/后缀/一元）
  6. 运算符优先级与结合性闭集表（比较与等同档**非结合**；E0104）
  7. 语法诊断段位（E0100–E0199 认领）

  章节正文另含 `## Examples (non-authoritative)` 示例节（用户裁决 2026-09-03；自带免责声明，只用已批准表面；样例源存变更目录，提升时逐字并入，机制同 Terminology 先例）。
- 扩展 `docs/spec/diagnostics.toml`：段位表 E0100–E0199 owner 转正（去掉 pending 注记）+ 段内结构注释 + 5 个新条目（E0101 解析歧义、E0102 续行 token 起始语句、E0103 赋值用作表达式、E0104 非结合运算符链、E0105 意外 token）；E0100 预留、E0106–E0199 预留。

## 影响层

- **spec**：第 2 章 ADDED；注册表文件扩展（同一变更内，新义务首次执行）。
- 不触及 process/docs/compiler/stdlib/tooling（注册表机制与检查器已就绪，本变更只是其使用者）。

## 影响范围

- **所有后续内容章节**：控制流/函数/类型/声明的产生式以本章骨架为宿主插入；新增运算符或改变结合性 = 本章闭集表的 MODIFIED 增量 + 破坏性变更。
- **注册表**：E0100–E0199 从 pending 转正，后续语法诊断码在本段内扩展。
- **与 v0.8 的关系**：§21/§21.1 块表达式三规则作为候选素材重新裁决，但**显式分号不继承**（用户裁决，2026-09-03，见裁决记录）；§21.2 的语义规则留给对应章节；v0.8 无优先级表——本章为从零裁决，非继承。
- **派生不变量（记入，工具章节承接）**：行结构成为语义要素后，官方格式化器必须**保行**——不得合并或拆分源行（否则改变语句边界即改变语义）。本章只记不变量，不定义 fmt。
- **风险与不可逆性**：行接续规则、优先级表与块值规则是 1.0 前可调、1.0 后极难反转的语言表面决定；E01xx 码位一旦被工具引用即成稳定性承诺。

## 裁决记录

2026-09-03 用户裁决两项：

1. **块与分号：换行敏感 + 省略分号**（Swift/Kotlin 风格）。未取推荐项（显式分号 + 块值规则）与 v0.8 §21.1 基线——v0.8 的显式分号规则不继承。后果：行结构进入语义；分号推断算法必须是全闭集表（P4：解析唯一性经由表的完全性满足，歧义仍以 E0101 拒绝并具名竞争解释，不触发第 0 章例外机制）；格式化器保行成为派生不变量。
2. **比较/相等链：非结合，解析层直接拒绝**（E0104）——`a < b < c` 必须写 `(a < b) && (b < c)`。

5. **参考基线固定：通过。** 素材固定为 `refr/spec-0.8.md` §21、§21.1、§21.2、§21.2.1；显式分号经用户裁决不继承；优先级表为从零裁决（v0.8 无表）。
