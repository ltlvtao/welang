# Design: fn-types-closures

裁决 D1–D4 见 proposal 裁决记录；本文件记录其落地形态与推导。

## D1 一等构造器的否定与 E0704 终身语义

ch9:44 把「裸载荷构造器是否一等值」留给本章。裁决：否。E0704 的注册表条目（owner 0900-sum-types）描述已含「if at all」措辞，触发语义永久成立；9900:33 删码禁令下无残值问题。ch9 宿主句由悬置改为永久规则，场景 THEN 尾句同步（「first-class constructors are the function-types chapter's」→ 构造走调用形式/闭包包装）。构造器函数需求由闭包 `|r| Circle(r)` 等价覆盖——组合子场景 `.map(|r| Circle(r))` 生成侧无摩擦。

## D2 单一 gc 闭包与捕获的健全性论证

闭包一律 gc：双类别（非逃逸 byval 零成本 + 逃逸 gc）需要逃逸分析，判定非局部，违 P1。捕获健全性：gc 型绑定的 var 以追踪单元格为载体，闭包持引用逃逸后由 GC 追踪——引用捕获因此健全；value 类别/基类型按拷贝快照，快照不可变（体内赋值 E1003，局部绑定携带中间值）；byres 禁捕获（E1002）——闭包按构造可越出创建点，句柄外逸破坏 ch8 资源纪律的单一确定性释放点，与 ch11 E0903（resource 类别禁实现 Iterable）同一论证骨架：先物化再捕获。

可变捕获的唯一通道是 gc 单元格：`var c = Counter { n: 0 }`（gc record）+ 闭包内重绑 `c = ...` 为活突变；`var n: Int64`（基类型）拷贝捕获且体内赋值被 E1003 拒——计数器惯用形以 gc 包裹表达，示例已给。字段赋值不存在（ch8），故闭包内改 gc 记录只能经绑定重赋值或方法，语义无裂缝。

## D3 严格语境推断与 ch6 立场的一致性

ch6:53「parameter types are never inferred」指声明参数永不推断。裸参短闭包的参数类型取自**同一位置已写下的显式 fn 类型**（注解/形参声明/返回声明）——这是期望复制，不是从使用处推断；无期望即 E1001。标注参自含（`|x: Int64| x + 1`），处处合法。混合裸/标注参：期望补裸参、标注参与期望不符走 E0501（成文于 R4）。返回类型一律自体定型（block 值），有期望则校验一致。

## D4 fn 类型文法与 v0.8 偏离清单

`fn(T1, ..., Tn) -> T`：返回必写（类型位完整性，P5；无值=`-> ()` 经 ch8 unit）；参数无上限（随 ch6「zero or more」——若此处设 8 上限则 9 参声明 fn 无法类型化，自相矛盾）；单态（参数/返回皆类型引用；泛型 fn 是族非函数，值位 E1004）。**v0.8 偏离**：(a) effect 段 `fn(Int64) io -> Int64` 不继承——本规范未批准任何效应系统，空转文法违「一类事实只有一个权威位置」；若未来效应章批准，经 R1 修订进入并同步 ch7 场景示例。(b) v0.8 §13.5 完整语法即本设计之完整闭包形式，语义同源。

## D5 短闭包的文法定位与三大位置裁决

短形式坐落于 ch2 骨架之外（与 if/match 同层），体最大化（后缀与二元运算属体）。三个位置裁决均有既定码承接，零新机制：

1. **语句首位**：`|` 在 ch2 连续集内、语句起始类外——E0102 机制涌现，短形式不进语句起始类（丢弃闭包值本就 E0605）。
2. **二元/一元操作数位**：操作数位的 `|` 不合任何产生式——E0105；`1 + (|x| x)` 括号合法。词法分析佐证：`a | |x| x` 空格分词为两个 `|`，相邻 `a ||| x|` 则吞为 `||`——无论哪种，`|` 到达操作数位即拒绝，**不存在静默误析路径**（P4 复核）。
3. **实参位/绑定右侧/注解位**：表达式起点，`|` 即闭包开端——参数表由逗号定界，无歧义。

调用短闭包自身须括号 `(|x| x + 1)(2)`：体最大化使后缀属体，括号定接收者——与 Rust 同形。

4. **零参短闭包不存在（审查 F1 发现）**：`||` 是 ch1 逻辑或算子的单 token（maximal munch），`|| body` 永远吞为逻辑或——零参闭包唯一合法形是完整形式 `fn() -> ...`；短形式限 k≥1，参数表以 name 开列（`| |` 空格变体同样在参数首位遇 `|` 即 E0105）。R4 场景「No zero-parameter short form exists」机器断言之。

## D6 闭包体=函数体；E0401 语境扩展

block 值即返回值（ch2/ch6 单一机制复用）；`return` 从闭包返回不穿透外层 fn（v0.8 §22 注继承——控制流目标局部可判定，P1）；闭包体内 defer 于体退出执行（ch3 LIFO）。E0401 注册表 description 扩展一句：函数体语境=具名 fn + 闭包体；模块顶层与 defer 体仍无 return。属同变更描述维护（E0104/E0404/E0501 先例）。

## D7 E0501 承接签名一致性（零新码）

fn 值用于不一致的 fn 型位置是 ch7 一致性位置的自然实例（绑定对注解/实参对形参/返回对声明），消息串不变；ch10 no-variance/no-subtyping 立场延伸至 fn 型（`fn(Int64) -> Int64` 与任何其他签名互不相容）。签名族不设专属码——一码一义，签名错配就是类型错配。

## D8 宿主修改记账与场景继承

- ch2 Expression skeleton：keyword-led 句 +1 句；+1 场景（A closure form is used）；其余 4 场景逐字继承。
- ch7 Type references：枚举 +fn 型形式；「Unratified type syntax is rejected」标题保留、示例换 effect 段形式（真实未批准文法，收窄不删除——ch7 unratified 场景收窄先例）；+1 场景（A function type in an annotation slot）；其余 4 场景逐字继承。
- ch9 Variant constructors：悬置句→永久句；E0704 场景 THEN 尾句替换；其余 3 场景逐字继承。
- ch6/ch10/ch11 零条款修改：ch6 声明面本自足（fn 名值化由本章定义）；ch10 泛型方法非本章义务（zh:290 系揣测）；ch11 组合子边界不变更。
- D14 示例刷新（实现期披露）：ch9（pending 一等构造器行→E0704 拒绝形式、引言句）、ch7（Fn types 行兑现）、ch5（「组合子需闭包」表述）、ch11（「need function values」表述，若审定需要）。

## D9 诊断分配

段位 E1000–E1099 owner 1200-fn-types；E1000 边界保留；E1001 裸参闭包无期望 fn 型；E1002 byres 绑定被捕获；E1003 对捕获的 value 类别绑定赋值；E1004 泛型 fn 名用于值位置；E1005–E1099 保留（组合子变更在本段位内扩展的候选）。既有码复用：E0102（语句首位 `|`）、E0105（操作数位 `|`、malformed fn 型、effect 段、方法值）、E0501（签名一致性、标注参与期望不符）、E0605（丢弃闭包值）、E0704（裸载荷构造器，永久）。E0401 description 扩展（D6）。
